# 지역이해 암기 프로그램 PRD

- 문서 버전: v0.2
- 작성일: 2026-09-07
- 상태: 학습지 스캔본(1~14쪽, 23~31쪽) 반영 완료 · **15~22쪽(영남권·제주) 미수령**

---

## 1. 개요

### 1.1 배경
`지역이해` 수업의 시험 대비를 위해, 프린트로 배포된 지리 암기 자료(세계 지형 + 한국 지역)를
반복 학습할 수 있는 퀴즈 프로그램이 필요하다. 지도상의 **위치 ↔ 이름 ↔ 특징**을
세 방향으로 연결해서 외우는 것이 목표이므로, 단순 단어장 형태로는 부족하다.

### 1.2 목표
- 지도를 보고 **위치 → 이름**을 떠올리는 능력을 서답형으로 훈련한다.
- **이름 → 특징**을 5지선다로 훈련한다.
- 틀린 문제를 자동으로 추적해 반복 노출시킨다.

### 1.3 비목표 (이번 버전에서 하지 않는 것)
- 다중 사용자 계정 / 서버 기반 로그인
- 학습 데이터의 클라우드 동기화
- 지도 위 클릭(핀 찍기) 방식 문제 — v2 확장 후보
- 자동 문제 생성(AI) — 데이터는 프린트 기반 수기/반자동 입력

### 1.4 성공 기준
- 시험범위 전체 항목에 대해 두 유형 문제가 모두 출제 가능하다.
- 오답 항목이 정답 처리될 때까지 반복 출제된다.
- 한 세션(20문항)을 5분 이내에 풀 수 있다.

## 2. 사용자

| 구분 | 설명 |
|---|---|
| 주 사용자 | 지역이해 수업 수강생 본인 (단일 사용자) |
| 사용 환경 | PC 브라우저 우선, 모바일 브라우저에서도 동작 (통학 중 학습) |
| 사용 시점 | 시험 2~3주 전부터 매일 10~20분 반복 |

**핵심 사용자 스토리**
1. 시험범위 프린트를 데이터로 등록해두고, 앱을 열면 바로 퀴즈를 시작하고 싶다.
2. 지도에 표시된 지역이 어디인지 이름을 직접 타이핑해서 확인하고 싶다.
3. 이름은 아는데 특징을 헷갈리는 항목을 객관식으로 확인하고 싶다.
4. 틀린 것만 모아서 다시 풀고 싶다.
5. 세계 파트 / 한국 파트를 나눠서, 또는 "강만", "섬만" 골라서 풀고 싶다.

## 3. 학습 콘텐츠 범위

실제 학습지(2026 지역 이해)를 기준으로 확정한 범위입니다. 총 **131개 항목**.

학습 범위는 **학습지 대단원 구조**를 그대로 따른다.
큰 틀 두 개(한국지리 / 세계지리) 아래에 학습지 단원 번호대로 배치하고,
한 단원에 성격이 다른 항목이 섞이면 세부 갈래로 한 번 더 나눈다.

### 3.3 빈칸 처리 방침

학습지에서 비어 있던 빈칸은 문맥과 지도상 위치로 추론해 채웠고,
근거와 불확실 항목을 `docs/빈칸-정답-정리.md`에 전부 기록했다.
수업 필기와 대조해 수정할 항목은 그 문서의 마지막 절에 모아 두었다.

### 3.4 각주는 시험 범위가 아니다

학습지 하단 각주는 이해를 돕기 위한 설명이므로 출제되지 않는다.
따라서 **각주에만 나오는 서술은 퀴즈 데이터에 넣지 않는다.**
본문 빈칸의 답을 각주가 가리키는 경우(예: 카리브해 ⑯ 앤틸리스 제도)는
답 자체가 본문이므로 그대로 둔다. 제외한 목록은 `docs/빈칸-정답-정리.md`에 있다.

### 3.5 정답 지도 PDF

퀴즈와 별개로, 학습지 항목 131곳을 지도 위에 이름과 특징까지 적은
정답본을 `docs/지역이해-정답지도.pdf`로 만든다(굿노트 필기용).
A4 세로 9쪽, 위쪽에 지도·아래쪽에 지역별 특징. 완전 벡터라 확대해도
깨지지 않고 글자 검색이 된다. 지도는 학습지 스캔본이 아니라
Natural Earth·GSHHG 공개 자료로 새로 그린다.

### 3.6 이번 버전에서 문제로 만들지 않은 것

학습지의 개념 설명(지역성·동질지역·기능지역·점이지역), 통계표(도청 소재지·혁신도시·
도별 인구 1위 도시), 자연환경 서술(강원 기후·호남 지형)은 지도 기반 문제로 만들기
어려워 퀴즈 데이터에는 넣지 않고 `docs/빈칸-정답-정리.md`의 암기 자료로만 두었다.
필요하면 지도 없는 '개념' 카테고리로 5지선다만 추가할 수 있다.

## 4. 데이터 모델

### 4.1 항목(Item) 스키마
모든 문제는 하나의 `item` 레코드에서 파생된다.

```jsonc
{
  "id": "world_river_danube",        // 고유 ID
  "mapId": "world_europe",           // 어느 지도 이미지 위에 표시할지
  "category": "river",               // peninsula | river | lake | island | kr_region ...
  "scope": "world",                  // world | korea  (시험범위 분리용)
  "name": "다뉴브강",                 // 정답(대표 표기)
  "aliases": ["도나우강", "Danube"],   // 서답형 정답 허용 표기
  "marker": {                        // 지도 위 표시 위치 (이미지 기준 백분율)
    "type": "point",                 // point | path | area
    "x": 54.2, "y": 47.8,
    "path": [[52.1,44.0],[55.3,49.2]] // type이 path일 때만 (강 등 선형 지형)
  },
  "features": [                      // 특징 — 5지선다 정답 후보
    "유럽에서 두 번째로 긴 강",
    "10개국을 지나 흑해로 유입되는 국제하천"
  ],
  "hint": "독일 남부에서 발원",        // 서답형 힌트(선택)
  "tags": ["유럽", "국제하천"],        // 오답 보기 선정 및 필터용
  "note": "프린트 3쪽"                // 출처 메모(선택)
}
```

### 4.2 지도(Map) 스키마
```jsonc
{
  "id": "world_europe",
  "title": "유럽 지도",
  "image": "assets/maps/world_europe.png",
  "scope": "world"
}
```

### 4.3 데이터 파일 구성
```
data/
  maps.json          # 지도 목록
  items.world.json   # 세계 파트 항목
  items.korea.json   # 한국 파트 항목
assets/maps/*.png    # 지도 이미지
```

### 4.4 데이터 입력 방식 (프린트 → 데이터)
1. 프린트를 이미지/PDF로 전달받는다.
2. 항목명·특징 텍스트를 JSON으로 정리한다.
3. **마커 좌표 지정 도구**(내장 관리자 화면, §6.5)에서 지도 이미지를 띄우고
   각 항목을 클릭해 `marker` 좌표를 찍는다 → JSON으로 내보내기.
   - 좌표 입력이 가장 손이 많이 가는 작업이므로 이 도구는 v1 필수 범위에 포함한다.

## 5. 문제 유형

### 5.1 유형 A — 서답형 (지도 → 이름)
- **화면**: 지도 이미지 + 해당 항목 위치에 마커(핀/하이라이트 선) 표시
- **질문**: "표시된 **강**의 이름은?" (카테고리를 함께 제시해 모호성 제거)
- **입력**: 텍스트 입력 + Enter 제출
- **채점 규칙 (정답 정규화)**
  1. 앞뒤 공백 제거, 모든 공백 제거
  2. 대소문자 무시
  3. 괄호 안 내용 무시: `강원(특별자치)도` → `강원도`
  4. `aliases` 중 하나와 일치하면 정답
  5. **접미어 관대 처리**: `강/江`, `호/호수`, `반도`, `섬/도`, `도/특별자치도/광역시` 등
     지형 접미어는 있어도 없어도 정답 (예: "다뉴브" = "다뉴브강")
  6. **오타 허용**: 편집거리(Levenshtein) ≤ 1이면 "거의 정답" 처리 →
     정답으로 인정하되 화면에 정확한 표기를 강조 표시
- **피드백**: 정답/오답 즉시 표시 + 정확한 이름 + 해당 항목의 특징 전체 노출(복습 효과)
- **보조 기능**: 힌트 버튼(1회, `hint` 필드 노출 — 사용 시 해당 문항은 "힌트 사용"으로 기록)

### 5.2 유형 B — 5지선다 (이름/위치 → 특징)
- **화면**: 항목 이름(+선택적으로 지도 마커) 제시
- **질문**: "**다뉴브강**에 대한 설명으로 옳은 것은?"
- **보기**: 5개 (정답 1 + 오답 4)
- **오답 보기 생성 규칙 (우선순위 순)**
  1. **같은 카테고리**의 다른 항목 특징에서 추출 (강 문제 → 다른 강의 특징)
  2. 부족하면 같은 `scope` 내 다른 카테고리에서 보충
  3. 그래도 부족하면 전체 풀에서 보충
  4. 정답 문구와 동일하거나 해당 항목의 다른 `features`와 겹치는 문구는 제외
     (한 항목의 특징이 여러 개일 때 "정답이 2개"가 되는 사고 방지)
  5. 보기 순서는 매 출제 시 셔플
- **역방향 변형(선택 토글)**: "다음 설명에 해당하는 지역은?" — 특징 제시 → 이름 5지선다

### 5.3 출제 규칙
- 한 항목은 두 유형 모두에서 출제될 수 있다.
- `features`가 없는 항목은 유형 B에서 제외된다(데이터 검증에서 경고).
- 한 세션 내 동일 항목 중복 출제 금지(오답 재출제 모드는 예외).

## 6. 기능 요구사항

### 6.1 학습 세션 설정 (시작 화면)
| 설정 | 옵션 | 기본값 |
|---|---|---|
| 큰 틀 | 한국지리 / 세계지리 (각각 전체 선택·해제) | 전체 |
| 대단원 | 학습지 단원 단위로 켜고 끔 | 전체 |
| 세부 갈래 | 단원 안에서 반도/섬, 바다·만/호수/해협 등 | 전체 |
| 문제 유형 | 서답형만 / 객관식만 / 혼합 | 혼합 |
| 문항 수 | 10 / 20 / 30 / 전체 | 20 |
| 출제 순서 | 랜덤 / 오답 우선 | 오답 우선 |

### 6.2 퀴즈 진행 화면
- 상단: 진행률 (`7 / 20`), 현재 점수, 남은 시간(선택)
- 본문: 지도 + 마커 / 질문 / 입력 또는 보기
- 하단: 제출, 힌트, 건너뛰기(오답 처리)
- 키보드 지원: `Enter` 제출·다음, `1~5` 보기 선택 (모바일 제외)

### 6.3 결과 화면
- 총점, 정답률, 유형별 정답률, 카테고리별 정답률
- 틀린 문항 리스트 (항목명 · 내 답 · 정답 · 특징)
- "틀린 것만 다시 풀기" 버튼

### 6.4 오답 노트 / 반복 학습
- 항목별 학습 상태 저장: `정답 횟수`, `오답 횟수`, `마지막 학습일`, `연속 정답`
- **가중 출제**: 오답 횟수가 많고 최근에 틀린 항목이 먼저 나온다.
- **졸업 규칙**: 연속 정답 3회 → 출제 가중치 최소화(`숙달` 표시).
- 전체 진도 대시보드: 카테고리별 `미학습 / 학습중 / 숙달` 개수

### 6.5 데이터 관리자 화면 (v1 포함)
- 지도 이미지 업로드/선택
- 항목 목록 편집(이름, 별칭, 특징, 태그)
- **지도 클릭으로 마커 좌표 지정** (점/선 모두 지원)
- JSON 내보내기 / 가져오기
- 데이터 검증: 특징 없는 항목, 좌표 없는 항목, 중복 이름 경고

### 6.6 저장
- 학습 기록은 브라우저 `localStorage`에 저장 (단일 사용자, 서버 불필요)
- 설정 화면에서 기록 JSON 내보내기 / 가져오기 / 초기화 제공

## 8. 기술 스택 (제안)

- **프론트엔드**: HTML + 바닐라 JavaScript — 빌드 도구·의존성 없음
- **상태/저장**: React state + `localStorage` (외부 DB 없음)
- **지도 렌더링**: 학습지 지도를 그대로 잘라 쓰고, 두 가지 방식을 병용
  1. **번호 지도**(수도권·충청·강원·호남·세계): 학습지에 이미 번호가 인쇄되어 있으므로
     좌표 없이 "지도의 N번"으로 출제 → **마커 좌표 입력 작업이 통째로 불필요**
  2. **백지도**(17개 시·도): 번호가 없으므로 `marker:{x,y}` 백분율 좌표로 붉은 원 표시
- **배포**: `build.py`로 데이터·지도를 모두 인라인한 **단일 HTML 파일**을 만들어 배포한다.
  파일 하나만 옮기면 되므로 폴더 구조가 깨지거나 상대 경로가 어긋날 여지가 없다.

> **실제 채택안(v1)**: 빌드 없는 **단일 `index.html` + `data/items.js`**.
> 번호 지도 덕분에 좌표 입력이 거의 필요 없어져 관리자 화면의 필요성이 사라졌고,
> React·Vite를 도입할 이유가 없어졌다. 항목 추가는 `data/items.js`에 객체 하나를 넣으면 끝난다.
